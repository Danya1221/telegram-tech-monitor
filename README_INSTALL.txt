TECH MONITOR

Мониторинг новых сообщений в выбранных Telegram-группах и каналах с двух
пользовательских аккаунтов. Совпадения приходят владельцу в личку с ботом.
Список чатов кэшируется для быстрого поиска и перелистывания; запросы,
аккаунты, выбранные чаты и очередь уведомлений хранятся в PostgreSQL.

Railway Start Command: python main.py

Variables:
API_ID
API_HASH
BOT_TOKEN
DATABASE_URL — подключение к PostgreSQL
ADMIN_ID — Telegram ID владельца (рекомендуется задать до первого запуска)

Optional:
ANALYTICS_TZ=Europe/Moscow
MONITOR_INTENT=buy — по умолчанию покупки и короткие названия товаров;
                    объявления «Продам», «В наличии», «Прайс» пропускаются.
MONITOR_INTENT=all — также мониторить предложения продавцов.

После запуска открой личку с ботом: /start, /login, /queries, /chats.
Коды входа и пароль 2FA вводятся только в личке. Управление из групп закрыто.
Если ADMIN_ID не задан, владельцем становится первый пользователь /start
в личке. Настройки и сессии находятся в твоей PostgreSQL; не публикуй их.

Подбор:
- iPhone не заменяется Xiaomi/OnePlus через исключение короткого названия;
- Pro, Pro Max и базовая версия различаются; буквенные суффиксы сохраняются;
- телефон не совпадает с чехлом/стеклом/зарядкой;
- соседние товарные строки не обмениваются памятью/цветом;
- допускается безопасное продолжение «Samsung S26» + «Black 256GB»;
- память телефона можно писать без GB; известные русские написания нормализуются;
- цвета оправы и линз проверяются раздельно, если они явно указаны;
- /test использует тот же подбор и режим намерения, что живой мониторинг.

SIM проверяется отдельно: eSIM означает версию только с eSIM и не совпадает
с 1SIM+eSIM. SIM требует физическую SIM и допускает сочетание SIM+eSIM;
явные 1SIM и 2SIM различаются. Если SIM в сообщении не указана, заданное
требование не считается подтверждённым. Страна не используется для угадывания.

Доставка:
Совпадение сначала сохраняется в notification_outbox. Задержка — 15 секунд.
Непосредственно перед отправкой снова проверяются запрос, чат и аккаунт.
Сам текст также повторно проходит текущий фильтр: старое задание очереди
не сможет отправить совпадение, которое новая версия уже отклоняет.
Неотправленные задания остаются в PostgreSQL при перезапуске. Сетевые
ошибки и временные ограничения Telegram повторяются с задержкой.
Антидубль и аналитика фиксируются только после успешной отправки.
Одинаковый запрос одного автора в нескольких чатах подавляется на 120 секунд.

/status — аккаунты, запросы, чаты и состояние очереди.
Строка «Фильтр» показывает версию распознавания запущенного процесса.
/retryfailed — повтор постоянных ошибок, например после разблокировки бота.
/retryfailed uncertain — повтор заданий с неясным исходом. Сначала проверь
личку: если процесс завершился во время отправки, сообщение могло дойти.
В таком случае автоматический повтор отключён, чтобы не создавать дубли.
При сетевом обрыве после принятия сообщения Telegram повтор также может
создать дубль: Bot API не предоставляет ключа идемпотентности отправки.

Обновление создаёт таблицу очереди автоматически. Существующие аккаунты,
запросы, выбранные чаты, аналитика и старые отметки seen_messages сохраняются.
Оставь один экземпляр приложения с данным BOT_TOKEN/DATABASE_URL.

Проверки:
pip install -r requirements.txt
python -m unittest discover -s tests -v

Без TEST_DATABASE_URL выполняются локальные проверки, 7 сценариев PostgreSQL
пропускаются. Для проверки БД задай TEST_DATABASE_URL на тестовую PostgreSQL:
тесты создают и удаляют только собственные временные схемы. GitHub Actions
поднимает отдельную PostgreSQL 16 и выполняет полный набор.

Реальный вход в Telegram, живые группы и отправка с твоими ключами проверяются
после развёртывания. Сначала проверь примеры через /test и одну тестовую группу.
